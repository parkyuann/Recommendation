# VOD 하이브리드 추천 시스템

행동 로그 기반 협업 필터링과 콘텐츠 메타/텍스트 기반 신호를 결합해,  
**개인화 품질과 콜드스타트 대응력을 동시에 확보**하는 것을 목표로 직접 설계한 추천 시스템 프로젝트입니다.

---

## 1. 프로젝트 목표

### 해결하고자 한 문제

- 시청 이력이 충분한 사용자에게는 더 정교한 개인화 추천이 필요함
- 신규/저활동 사용자에게는 협업 필터링 단독으로 추천 품질 확보가 어려움
- 인기 편향이 강해지면 추천 다양성과 탐색성이 감소함

### 설계 목표

- **정확도**: 사용자 취향과 가까운 아이템 상위 노출
- **강건성**: 사용자 상태(신규/기존)에 따라 동작 가능한 추천 경로 확보
- **다양성**: 점수 상위권이 유사 아이템으로만 채워지는 현상 완화
- **서비스성**: API에서 모델/벡터 아티팩트를 재사용 가능한 구조로 운영

---

## 2. 모델 설계 개요

프로젝트는 성격이 다른 두 계층의 추천 모델로 구성됩니다.

### A. 오프라인 학습/실험 계층 (`collaborative_filtering/hybrid_recommendation_py`)

- 사용자-아이템 상호작용 데이터로 **ALS 행렬분해** 수행
- 아이템 메타데이터를 활용해 **콘텐츠 기반 신호** 생성
- 인기/기본 점수를 보조 신호로 결합
- 최종 추천 점수는 가중합 형태로 계산
  - `cf_weight`: 협업 필터링 기여도
  - `cb_weight`: 콘텐츠 기반 기여도
  - `pop_weight`: 인기 기반 기여도
  - `diversity_factor`: 다양성 보정 계수

즉, 단일 알고리즘이 아니라 **협업 + 콘텐츠 + 인기 보정의 앙상블 전략**입니다.

### B. 온라인 서빙 계층 (`hybrid_filtering/src`)

FastAPI 기반 추천 API에서 다음 자산을 함께 사용합니다.

- ALS 모델 및 사용자/아이템 인덱스 매핑
- TF-IDF 벡터, 그룹 벡터, 전처리된 희소행렬
- 사용자 이력/선호도 맵, 아이템 메타정보(장르/국가/키워드/포스터)

요청 처리 시 사용자 상태에 따라 분기합니다.

- **기존 사용자**: 이력 기반 하이브리드 추천 수행
- **신규 사용자**: 선호도 기반 추천 경로로 전환(콜드스타트 대응)

---

## 3. 추천 로직 설계 의도

### 왜 하이브리드인가

- 협업 필터링은 개인화 성능이 좋지만, 이력 부족 상황에 취약함
- 콘텐츠 기반은 콜드스타트에 강하지만, 행동 패턴 기반 미세 취향 반영에는 한계가 있음
- 두 접근을 결합하면 각 방식의 약점을 상호 보완할 수 있음

### 왜 가중합 구조인가

- 데이터 특성/서비스 목표에 맞게 신호 비중을 조정하기 쉬움
- 실험 단계에서 하이퍼파라미터 튜닝과 A/B 비교가 용이함
- 운영 단계에서 정책적 제어(예: 다양성 강화)가 가능함

---

## 4. 추론 파이프라인

1. 사용자 식별 및 시청 이력 조회  
2. 신규/기존 사용자 분기  
3. 후보군 점수 계산(ALS + 콘텐츠/메타 신호 결합)  
4. 다양성/정렬 규칙 반영 후 Top-N 반환  

대용량 아티팩트(`pkl`, `npz`)는 서버 초기화 시 선적재해, 요청마다 재계산을 최소화하도록 설계했습니다.

---

## 5. 평가 및 성능 기록

이 프로젝트는 오프라인 지표 실험보다, 실제 서비스 환경에서 사용자 체감 품질을 먼저 확인하는 방식으로 검증했습니다.

### 실제 진행한 검증 방식

- AWS에 추천 서비스를 배포한 뒤, 주변 지인들에게 테스트 링크를 공유
- 사용자별로 추천 콘텐츠 8개를 제시하고, "내 취향에 맞는 콘텐츠 개수"를 직접 체크하는 방식으로 수집
- 클러스터링 추천, 장르 TF-IDF, 장르별 추천, 키워드별 추천, 하이브리드 추천, 시대별 추천 등 여러 설계안을 동일 조건으로 비교
- 각 모델의 평균 적중 개수(8개 중)로 성능을 판단

### 테스트 결과 요약

- **하이브리드 추천이 평균 4.6/8로 가장 높은 점수**를 기록
- 단일 신호 기반 모델(장르/키워드/시대 등)보다, 사용자 행동 + 콘텐츠 정보를 함께 쓰는 하이브리드 구조가 더 안정적으로 높은 만족도를 보임
- 특히 "취향에 맞는 추천이 완전히 비지 않는다"는 피드백이 많았고, 실사용 관점에서 가장 일관된 결과를 보였음

### 해석

- 정량 지표(평균 적중 개수)와 정성 피드백(추천 이유 체감)을 함께 봤을 때, 본 프로젝트 목적이었던 "개인화 품질 + 콜드스타트 완화"에 가장 가까운 모델은 하이브리드 추천으로 판단했다.
- 다만 이 평가는 소규모 사용자 테스트 기반이므로, 이후에는 로그 기반 오프라인 지표(Precision@K, Recall@K, NDCG@K)와 온라인 지표(CTR, 재생 전환율)까지 확장해 검증할 계획이다.

---

## 6. 한계와 개선 방향

### 현재 한계

- 실험 노트북과 서비스 코드가 함께 존재해 재현 파이프라인 표준화 여지가 있음
- 데이터/아티팩트 버전 관리 체계(예: MLflow, DVC)가 명시적이지 않음
- 가중치 기반 앙상블은 해석 가능성이 높지만, 자동 최적화 범위는 제한적임

### 개선 계획

- 시계열 기반 데이터 분할로 시간 누수 방지 평가 체계 강화
- 하이퍼파라미터 탐색 자동화 및 사용자 세그먼트별 가중치 최적화
- 재순위화(re-ranking) 단계에서 다양성/신선도 제약을 명시적으로 적용
- 피드백 루프를 반영한 주기적 재학습 파이프라인 구축

## 7. 프론트엔드

`src`는 React 기반 UI 레이어로, 모델 결과를 사용자에게 전달하는 역할에 집중합니다.

- 주요 라우트: `/login`, `/signup`, `/main`, `/mypage`
- 추천 로직은 프론트엔드가 아니라 Python 모델/API 계층에서 처리
